# 实施计划 — JobTracker

每步完成后由用户验证，验证通过后再进入下一步。

---

## Step 1：项目骨架 + Hash 路由

**目标**：建立 `index.html`，引入所有 CDN 依赖，实现 5 个路由占位页面的切换。

**交付物**：
- `index.html` 文件存在
- 顶部导航栏（列表 / 设置）
- Hash 变化时页面内容切换（列表、添加、详情、浏览、设置各显示对应文字占位）
- Vue 3 + Tailwind 正常加载，无控制台报错

**验证**：用浏览器打开 `index.html`，手动修改地址栏 hash，确认内容切换正常。

---

## Step 2：localStorage 数据层

**目标**：封装所有读写操作，确保数据持久化。

**交付物**：
- `loadApplications()` / `saveApplications()` 函数
- `loadSettings()` / `saveSettings()` 函数
- 每次修改后自动写入 localStorage
- 导出 JSON 按钮（下载文件）
- 导入 JSON 按钮（读取文件并覆盖当前数据，有确认弹窗）

**验证**：添加一条假数据，刷新页面后数据仍在；导出 JSON 文件可正常打开；导入同一文件后数据不变。

---

## Step 3：投递列表页

**目标**：展示全部投递记录，支持按状态筛选。

**交付物**：
- 卡片列表，每张卡片显示：公司名、岗位、投递日期、状态标签（带颜色）
- 状态筛选下拉（全部 + 6 个预设 + 自定义）
- 每张卡片有「查看详情」和「面试前浏览」两个入口
- 列表为空时显示引导提示「点击右上角添加第一条投递」
- 「添加投递」悬浮按钮或顶部按钮

**验证**：用 localStorage 预置 3 条不同状态的记录，列表正确渲染；切换筛选条件，列表正确过滤。

---

## Step 4：添加 / 编辑投递表单

**目标**：完整的表单，覆盖所有字段，支持新增和编辑。

**交付物**：
- 字段：公司名（必填）、岗位（必填）、投递日期（日期选择器，默认今天）、状态（下拉）、公司简介（多行文本）
- JD 区域：多行文本输入，「AI 格式化」按钮（Step 7 实现 AI，此步仅占位显示「功能待接入」）
- 保存按钮 → 写入 localStorage → 跳转列表
- 取消按钮 → 返回列表
- 编辑模式：从 URL `#detail/{id}?edit=true` 进入，预填数据
- 删除按钮（有确认弹窗）

**验证**：新增一条记录，回到列表可见；再次进入编辑，修改后保存，数据已更新；删除记录后列表消失。

---

## Step 5：公司详情页（信息 + JD Tab）

**目标**：详情页「基本信息」Tab，展示并允许内联编辑。

**交付物**：
- Tab 导航：基本信息 / 面经（面经 Tab 在 Step 6 实现）
- 基本信息 Tab 展示：公司名、岗位、状态（可直接点击切换）、投递日期、公司简介
- JD 区域：显示格式化后的 Markdown（用 marked.js 渲染）；若无格式化结果则显示原始文本
- 「编辑」按钮跳转编辑表单

**验证**：进入某公司详情，信息正确展示；状态标签可点击切换并持久化；JD 原文粘贴后以 Markdown 渲染。

---

## Step 6：面经 Tab — 面试记录增删改查

**目标**：在详情页面经 Tab 管理多场面试记录。

**交付物**：
- 面经 Tab 列表：按日期倒序，每条显示日期、轮次、题目数
- 「添加面试记录」按钮 → 打开表单（可在页内展开或跳转子页）
- 面试记录表单字段：日期、轮次（下拉 + 自定义）、备注
- 题目列表：动态增删行，每行有「题目」和「我的回答」两个多行输入框
- 保存 / 取消 / 删除

**验证**：添加一场包含 3 道题的面试记录，刷新后数据不丢；编辑其中一道题的答案并保存，内容更新正确。

---

## Step 7：设置页 — API Key + 简历上传

**目标**：配置 DeepSeek API Key 和简历，为 AI 功能铺路。

**交付物**：
- API Key 输入框（type=password），保存到 localStorage
- 简历上传：支持 PDF 和 .docx
  - PDF：用 PDF.js 提取文字层
  - .docx：用 mammoth.js 提取纯文本
  - 提取结果预览（前 200 字）
  - 扫描件 / 提取失败时显示降级提示，展示手动粘贴文本框
- 当前已上传简历文件名展示
- 自定义状态管理：列表展示、添加、删除

**验证**：上传 PDF 简历，预览正确显示文字内容；保存 API Key 后刷新页面，Key 仍存在（显示为 *** 脱敏）；添加自定义状态后在投递表单下拉中可见。

---

## Step 8：AI 功能 — JD 格式化

**目标**：在添加/编辑页实现「AI 格式化 JD」按钮。

**交付物**：
- 点击「AI 格式化」→ 调用 DeepSeek API
- 请求期间显示 loading 状态，按钮禁用
- 成功后将结果写入 `jdFormatted` 字段，在详情页以 Markdown 渲染
- 失败时显示错误提示，不清空原始 JD
- 未配置 API Key 时点击按钮，跳转提示设置页

**Prompt 模板**（固定，不暴露给用户）：
将下面的职位描述整理为结构化 Markdown，包含以下段落（如原文有对应内容）：职位概述、岗位职责、任职要求、加分项、薪资福利。保持原文关键信息，精简冗余措辞。

**验证**：粘贴一段真实 JD，点击格式化，返回结果结构清晰；断网时点击，显示错误不崩溃。

---

## Step 9：AI 功能 — 面试建议分析

**目标**：基于 JD + 简历，生成面试建议报告。

**交付物**：
- 「AI 分析」按钮在详情页 JD 区域下方
- 需要：JD 已格式化 + 简历已上传，否则按钮置灰并提示
- 调用 DeepSeek API，streaming 或一次性返回均可
- 结果以 Markdown 渲染，存入 `aiAnalysis` 字段
- 可重新分析（覆盖旧结果，有确认提示）

**Prompt 模板**：
你是一位资深求职顾问。以下是候选人的简历和目标岗位的 JD。请分析：1）简历与 JD 的核心匹配点；2）潜在短板及准备方向；3）面试中应重点强调的 2-3 个亮点；4）根据 JD 推断可能被问到的问题方向。用中文回答，Markdown 格式。

**验证**：在已有 JD 和简历的情况下点击分析，返回有实质内容的建议报告；未上传简历时按钮不可点击。

---

## Step 10：面试前浏览页

**目标**：`#review/{id}` 聚合只读页，面试前快速浏览。

**交付物**：
- 顶部：公司名 + 岗位 + 状态标签
- 公司简介区块
- 格式化 JD 区块（Markdown 渲染）
- AI 面试建议区块（Markdown 渲染）
- 面经区块：按日期倒序，每场面试展开显示所有题目 + 回答
- 「返回详情」按钮
- 页面整体适合连续阅读（适当间距，字体稍大）

**验证**：进入浏览页，信息完整显示；无面经时该区块显示「暂无面经记录」；无 AI 分析时该区块提示「尚未生成分析」。

---

## Step 11：收尾打磨

**目标**：修复已知问题，提升整体体验。

**交付物**：
- 所有表单输入有基本校验（必填字段提示）
- 列表按投递日期倒序排列
- 长文本截断（卡片 JD 显示前 100 字 + 展开）
- 空状态页友好提示
- 导出文件名带日期（`jobtracker-2025-05-10.json`）
- 测试：完整走一遍 4 个用户旅程，确认无明显 bug

**验证**：用户可完整走完「添加投递 → 记录面经 → 面试前浏览」全流程，无崩溃，无数据丢失。

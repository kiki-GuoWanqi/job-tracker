# JobTracker — AI 驱动的求职全流程管理工具

> **[🚀 点击在线体验](https://kiki-guowanqi.github.io/job-tracker/)** — 无需注册，打开即用，支持 DeepSeek / 千问 API Key 配置后解锁 AI 全功能

---

## 一、产品背景与用户痛点

### 目标用户

**应届生 / 校招求职者**：同期投递 30–80 家公司，战线长达 3–6 个月，在「投简历 → 笔试 → 多轮面试 → Offer 比较」各环节中面临严重的信息熵增和心智负担。

### 核心痛点（来自用户访谈）

| 痛点 | 现有工具的不足 |
|------|--------------|
| 投递进度散落在邮件/微信/各招聘平台 | Excel 手动维护成本高，容易漏更新 |
| 面试前临时抱佛脚，没有系统化复习材料 | 历史面经记在聊天记录里，检索困难 |
| 看完 JD 不知道自己哪里匹配、哪里欠缺 | 靠感觉投递，无法优先级排序 |
| 多个 Offer 到手时决策困难 | 薪资 / 公司 / 发展多维比较没有工具支撑 |
| 失败后缺乏系统复盘 | 没有记录就没有改进，反复在同一关卡挂掉 |

## 二、产品方案

### 设计原则

1. **零摩擦录入**：首次使用 30 秒内完成第一条投递记录；核心流程（添加 → 改状态 → 记面经）无需 AI 和配置
2. **AI 增强而非 AI 依赖**：没有 API Key 时产品完整可用；AI 是加速器，不是功能门槛
3. **隐私优先**：纯本地存储，所有 AI 请求从浏览器直连 API，服务端不经手任何用户数据
4. **单文件可部署**：整个产品是一个 `index.html`，GitHub Pages 零成本托管，用户可自己 fork 私有部署

### 功能地图

```
投递管理（核心）
├── 看板视图 — 状态机驱动，拖拽切换投递阶段
├── 日历视图 — 笔试/面试时间轴，防遗漏
└── 归档与复盘 — 失败记录保留，支持写复盘笔记

AI 辅助（增值）
├── JD 解析 — 粘贴/截图 → 结构化要点 + 岗位标签
├── 简历匹配打分 — 简历 × JD → 匹配度/优势/差距/建议
├── 定制招呼语 / 求职信 — 基于偏好 + JD 生成
├── 公司调研 — 一键生成公司业务/行业/团队背景简报
└── 面试建议 — 可能被问的问题 + 维度分析

面试准备系统
├── 面经记录 — 按场次结构化保存题目 + 笔记
├── AI 参考答案 — 每道题一键生成，对照复盘
└── 题库自测 — 隐藏答案模拟问答，三级评分（掌握/模糊/不会）

决策辅助
├── Offer 比较器 — 多维评分表 + AI 综合建议
└── 数据看板 — 漏斗转化率、投递趋势、渠道效果分析
```

## 三、AI 产品设计思路

### 为什么选 AI，选哪种 AI

求职准备中存在大量**高重复 + 高认知负担**的任务（读 JD、写材料、整理面经），这类任务用规则/模板无法覆盖，但 LLM 的泛化能力恰好适配。本产品选择的 AI 集成策略：

- **文本生成**：DeepSeek-V3 / 千问 作为主力（成本低、中文能力强），OpenAI / Claude 作为可选降级
- **视觉理解**：千问-VL 处理 JD 截图 OCR，避免用户手动转文字的摩擦
- **降级策略**：配置了 N 家 provider 时，任何单一服务不可用自动切换，减少「AI 突然坏了」的体验断点

### Prompt 工程决策

| 场景 | 关键设计 |
|------|---------|
| JD 格式化 | 要求输出固定 Markdown 结构（职责/要求/加分项），方便后续 AI 调用复用 |
| 匹配打分 | 注入用户求职偏好（城市/薪资/公司类型），让评分有个性化基准，而非纯 JD 维度 |
| 面试题生成 | 要求输出 JSON 数组，确保可编程处理（存库/显示/自测） |
| Offer 比较 | 多维评分表作为 context，让 AI 给出有数据支撑的建议而非泛泛而谈 |

### 产品决策取舍

- **不做 AI 自动填写进度**：用户投递状态更新是高意图操作，AI 干预会引入信任问题；保留手动操作确保数据可靠
- **不做社交/分享功能**：求职信息敏感，用户不希望数据上云；隐私承诺比社交功能更有价值
- **不做移动端 App**：核心用户在电脑上操作招聘网站，web 端覆盖主要使用场景，降低维护成本

## 四、关键功能设计细节

### 状态机 & 流转逻辑

```
待投递 → 已投递 → 简历筛选 → 笔试 → 面试（支持多轮）→ Offer / 已挂
                                                              ↓
                                                          归档（保留历史，可复盘）
```

设计要点：状态变更触发时间轴记录，形成每条投递的「完整生命周期视图」，而非简单的标签替换。挂科后进入归档，用漏斗分析在哪一关失败最多，指导后续准备策略。

### 题库自测系统

面试准备的核心难点：**知道答案 ≠ 能说出答案**。自测系统采用三级评分（好/模糊/不会），模拟真实面试节奏：

1. 显示问题，用户回想自己的答案
2. 点击「查看参考」后才展示 AI 生成的标准答案
3. 自我评分，不会的题目标记后置，形成专注弱点的练习循环

### 数据看板设计

漏斗图采用**绝对数字 + 视觉宽度编码**，而非百分比——求职阶段的样本量太小，百分比会产生误导（1 个 Offer / 2 个面试 = 50% 并无意义）。重点让用户看到绝对数量的差距，定位最需要改进的阶段。

## 五、技术架构（从产品视角）

| 决策 | 方案 | 产品价值 |
|------|------|---------|
| 架构 | 纯静态单页应用（Vue 3 CDN） | 零部署成本，用户可 fork 自用，无服务器运维风险 |
| 存储 | localStorage + JSON 导出/导入 | 数据完全由用户掌控，隐私可信，换设备可迁移 |
| AI 接入 | 浏览器直连 API，Key 存本地 | 服务端不经手用户数据，隐私承诺技术可验证 |
| 部署 | GitHub Pages | 自带 HTTPS，永久免费，URL 稳定 |

## 六、快速上手

1. **[打开在线地址](https://kiki-guowanqi.github.io/job-tracker/)** — 零注册，打开即用
2. 点击「+ 添加投递」录入第一条记录
3. 进入「设置」填写求职偏好（城市 / 薪资期望 / 公司类型），让 AI 建议更有针对性
4. （可选）配置 DeepSeek 或千问 API Key，解锁 JD 解析、匹配打分、面试建议等 AI 功能

**本地运行**：直接用浏览器打开 `index.html`，无需安装任何依赖。
